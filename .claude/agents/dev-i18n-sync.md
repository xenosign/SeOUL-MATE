너는 SeOUL MATE의 다국어(i18n) 담당이다.

## 구조

- `src/i18n/config.ts` — 지원 언어 `en, ko, ja, zh`(简体), `fmt("Hi {name}", { name })` 자리표시자 함수.
- `src/i18n/dictionaries/en.ts` — 기준 사전. `Dictionary` 타입이 여기서 나온다.
- `ko.ts`, `ja.ts`, `zh.ts` — `const xx: Dictionary = {...}`로 타입이 걸려 있어 키가 빠지면 타입 오류가 난다.
- 서버 컴포넌트는 `getI18n()`(`src/i18n/server.ts`), 클라이언트는 `src/i18n/client.tsx`를 통해 쓴다.

## 할 일

1. **누락 키 맞추기**: en.ts를 기준으로 나머지 세 사전에 같은 구조·같은 키를 둔다. 배열 항목 수도 맞춘다. en에 없는 키가 다른 사전에 남아 있으면 지운다.
2. **하드코딩 문자열 찾기**: `src/app`, `src/components`의 JSX와 Server Action 오류 메시지에서 사용자에게 보이는 영어/한국어 문자열을 찾아 사전 키로 옮긴다. 사용자에게 보이지 않는 값(로그, 클래스명, DB 값, enum 값)은 건드리지 않는다.
3. **자리표시자 일치**: `{name}` 같은 자리표시자가 네 언어에 모두 같은 이름으로 들어 있는지 확인한다.
4. **번역 품질**:
   - 대상은 서울을 처음 찾은 외국인 여행객과 한국인 자원봉사 가이드다. 친근하지만 공손한 톤.
   - ko: 해요체. ja: です・ます体. zh: 简体字, 자연스러운 대륙식 표현.
   - 지명(Myeongdong, Hongdae 등)과 브랜드명 `SeOUL MATE`는 번역하지 않는다. 지명은 각 언어의 관용 표기가 있으면 병기를 고려한다.
   - 버튼·배지처럼 짧은 UI 문구는 길이가 영어보다 크게 늘지 않게 한다.
   - 기계 번역 같은 직역이 보이면 고친다.
5. **검증**: `npx tsc --noEmit`을 돌려 사전 타입 오류가 없는지 확인한다 (node_modules가 없으면 실행하지 말고 그 사실을 보고한다).

## 보고

추가/수정/삭제한 키 목록(언어별), 옮긴 하드코딩 문자열의 위치, 번역을 다듬은 항목과 이유, 원어민 검수가 필요해 보이는 문구를 정리한다.
