# 신고·차단·제재 정책과 운영 절차

- 작성: biz-trust-safety / 작성일·조사일: 2026-10-17
- 상태: **초안**. 응답 시간과 담당자는 **사용자 결정이 필요하다**.
- 기준 구현: `supabase/migrations/0003_signup_attributions_and_reports.sql`, `src/app/chats/[roomId]/report/`, `src/lib/types.ts:47-55`
- 면책: 작성자는 변호사가 아니다. 보관 기간, 수사기관 협조, 제재 관련 약관 조항은 출시 전에 법률 전문가 검토가 필요하다.

---

## 0. 결론

- **지금 있는 것**: 채팅방 안 신고. 사유 6가지, 상세 1,000자, 상대가 메시지를 보낸 뒤에만, 같은 방·같은 상대에게 1회, 신고자당 하루 10건. 최근 메시지 50개와 상대의 당시 이름을 스냅샷으로 저장한다. 처리는 대시보드에서 `resolved_at`을 채우는 방식이다.
- **지금 없는 것**: 신고 알림, 차단, 계정 정지, 처리 결과 기록, 신고자에게 결과 알림. **신고 알림이 없으면 아래의 응답 시간을 지킬 수 없다.** 그래서 신고 알림(M-1)과 차단(M-2), 계정 정지(M-3)는 여행객 대상 홍보 전에 필요하다.
- **우선 처리**: `safety` → `money` → `harassment`·`inappropriate` → `spam`·`other` 순서로 처리한다.
- **제재**: 경고 → 7일 정지 → 영구 정지. 중대한 위반은 바로 영구 정지한다.
- **스냅샷 보관 제안**: 제재 없이 종결된 신고는 종결 후 6개월, 제재한 신고는 종결 후 1년이 지나면 메시지 스냅샷을 지운다. 제재 기록(누가, 왜)은 3년까지 남긴다. 미처리 신고와 분쟁·수사 중인 신고는 지우지 않는다.

## 1. 현재 신고 기능 요약 (코드 기준)

| 항목 | 동작 | 근거 |
|---|---|---|
| 신고 가능자 | 채팅방 참여자가 같은 방의 상대를 신고 | `0003:72-86` |
| 조건 | 상대가 그 방에 메시지를 1개 이상 보낸 뒤 | `0003:82-85`, `actions.ts:34-40` |
| 중복 | 같은 (신고자, 상대, 방)은 1회 | `0003:57`, 중복이면 "already" 표시 |
| 속도 제한 | 신고자당 24시간 10건 | `0003:98-103` |
| 사유 | `harassment / inappropriate / money / safety / spam / other` | `0003:41-42`, `types.ts:47-55` |
| 스냅샷 | 상대의 당시 `display_name`, 방의 최근 메시지 50개(양쪽 메시지 모두) | `0003:105-122` |
| 삭제 내성 | 요청·계정을 지워도 신고 행은 남음(`on delete set null`) | `0003:46-48` |
| 열람 | 신고자는 자기 신고만 봄. 신고당한 사람은 알 수 없음 | `0003:65-67` |
| 처리 | 팀이 대시보드에서 `resolved_at`을 채움 | `0003:54` |

알려진 빈틈:
- **B1** 매칭된 상대가 앱 채팅에 메시지를 하나도 보내지 않고 외부 메신저로만 연락한 뒤 문제를 일으키면 신고할 수 없다.
- **B2** 신고당한 사람이 계정을 지우면 `reported_user_id`가 null이 된다. 같은 구글·카카오 계정으로 다시 가입해도 이전 신고와 연결할 수 없다(제재 회피).
- **B3** 처리 결과(무엇을 했는지)를 기록할 칸이 없고 `resolved_at`만 있다.
- **B4** 신고자에게 처리 결과를 알릴 수단이 없다(앱 알림 없음. 이메일은 `auth.users`에만 있음).

## 2. 담당과 확인 주기

| 항목 | 제안 | 결정 |
|---|---|---|
| 신고 운영 담당 | 최소 1명 + 백업 1명. 대시보드 접근 권한은 이 두 사람에게만 준다 | **사용자** |
| 확인 방법(알림 기능 전) | 하루 2회(10:00, 21:00 KST) 대시보드에서 `reports_open_idx` 기준으로 미처리 신고를 확인 | 사용자 |
| 확인 방법(M-1 후) | `safety`·`money` 신고가 들어오면 즉시 이메일이나 메신저 알림. 나머지는 하루 1회 요약 | 개발 |

### 응답 목표 (알림 기능 M-1이 있다는 전제, **가설**: 소규모 팀 기준)

| 우선 | 사유 | 1차 확인 | 조치 결정 |
|---|---|---|---|
| P0 | `safety` | 알림 후 2시간 이내(09:00~23:00 KST). 그 외 시간은 다음 날 09:00 | 1차 확인 즉시 필요하면 임시 정지 |
| P1 | `money` | 12시간 이내 | 24시간 이내 |
| P1 | `harassment`, `inappropriate` | 24시간 이내 | 48시간 이내 |
| P2 | `spam`, `other` | 72시간 이내 | 7일 이내 |

- 같은 사람에 대한 신고가 2건 이상이면 사유와 관계없이 한 단계 올린다.
- **앱 문구에는 확정된 시간만 쓴다.** 확정 전에는 "We'll review it as soon as we can"으로 쓰고 시간을 약속하지 않는다.
- 신고 화면과 안전 수칙에 "위험하면 먼저 112"를 늘 함께 보여 준다. 앱의 신고는 긴급 대응 수단이 아니다.

## 3. 처리 절차

1. **열기**: 미처리 신고(`resolved_at is null`)를 오래된 순서가 아니라 **우선순위 순서**로 연다.
2. **맥락 확인**: `messages_snapshot`, `details`, 같은 `reported_user_id`의 다른 신고, 해당 방의 요청 상태(매칭 여부, 여행 날짜), 매칭 해제 기록(`match_events`가 생기면)을 본다.
3. **급한지 판단**: 여행 날짜가 오늘이나 내일이고 `safety`·`money`라면 바로 임시 정지(4장)를 먼저 하고 판단은 그 뒤에 한다.
4. **판단**: 4장의 위반 유형과 제재 표를 적용한다. 판단이 어려우면 백업 담당과 함께 본다.
5. **조치**: 제재를 실행하고(M-3, 또는 임시 수단), 필요하면 신고당한 사람에게 이메일로 알린다(7장 양식).
6. **기록**: `resolved_at`과 함께 결과(`resolution`), 메모, 처리자를 남긴다(M-4. 생기기 전에는 저장소 밖의 팀 비공개 시트에 신고 id 기준으로 기록하되, 이름·메시지 내용은 옮기지 않는다).
7. **신고자 안내**: 연락 수단이 생기면(B4) "처리했다"는 사실만 알린다. 상대에게 내린 제재 내용은 알리지 않는다.

**신고자 보호**: 1:1 채팅이라 제재를 하면 상대가 신고자를 짐작할 수 있다. 알림 이메일에 신고 내용, 신고자 이름, 신고 시각을 쓰지 않는다. 보복성 연락이 확인되면 그것만으로 영구 정지 사유가 된다.

**허위·악의적 신고**: 반복되는 허위 신고, 거절당한 데 대한 보복성 신고는 신고자에게 경고한다. 반복되면 정지한다.

## 4. 금지 행위와 제재

### 4.1 위반 유형

| 등급 | 유형 | 예 |
|---|---|---|
| **중대** | 폭력·위협, 성범죄·성적 강요, 미성년자에 대한 성적 접근, 금전 사기·갈취, 신원 도용, 신고자에 대한 보복 | 만남에서 신체 접촉 강요, 송금 요구 후 잠적 |
| **심각** | 반복 괴롭힘, 원치 않는 성적 메시지, 금전·선물·팁 요구, 유료 투어·상품 판매, 가게 수수료 목적 안내, 매칭 해제 후 계속 연락 | "가이드비는 5만원", "이 가게에서 사면 할인" |
| **일반** | 스팸·광고, 무례한 언행, 사전 연락 없는 노쇼 반복, 허위 프로필 정보 | 외부 링크 도배, 3회 이상 노쇼 |
| **연령** | 만 19세 미만 가입(기준 확정 후) | — |

### 4.2 제재 단계

| 등급 | 1회 | 2회 | 3회 |
|---|---|---|---|
| 중대 | **영구 정지** + 필요하면 수사기관 신고 안내(피해자에게 112 신고 권유) | — | — |
| 심각 | 7일 정지(사안에 따라 바로 영구 정지) | 영구 정지 | — |
| 일반 | 경고 | 7일 정지 | 영구 정지 |
| 연령 | 일시 정지 → 본인 확인 → 미성년이면 계정 삭제 | — | — |

- 위반 횟수는 최근 12개월 기준으로 센다(**제안**).
- **임시 정지**: `safety`·`money` 신고를 판단하는 동안 최대 72시간까지 정지할 수 있다. 위반이 아니면 해제하고 기록을 남긴다.
- 정지하면: 새 요청 작성, 채팅방 생성, 메시지 전송을 막는다. 그 사람의 열린 요청은 목록에서 숨긴다(M-3).

### 4.3 지금 당장 쓸 수 있는 임시 제재 수단 (M-3 전)

- Supabase Auth의 사용자 차단(`ban_duration`, 관리자 API나 대시보드)으로 로그인을 막는다. **확인 필요**: 이미 발급된 세션(액세스 토큰 유효 시간 동안)이 바로 끊기는지. 끊기지 않으면 토큰 만료까지 RLS가 계속 허용한다.
- 그 사람의 열린 요청은 대시보드에서 `cancelled`로 바꾼다(C1 이후에는 service role로 처리).
- 이 수단은 **로그를 남기지 않으므로** 3장 6번의 기록을 꼭 남긴다.

## 5. 이의 제기

- 제재 알림 이메일에 이의 제기 방법을 적는다: 받은 날부터 30일 안에 [연락 이메일]로 회신.
- 가능하면 처음 판단한 사람이 아닌 담당자가 다시 본다(백업 담당).
- 7일 안에 결과를 알린다. 결과는 유지, 감경, 해제 중 하나다.
- 이의 제기를 검토하는 동안에도 중대 등급 제재는 유지한다.

## 6. 신고 스냅샷 보관과 파기

신고 스냅샷에는 **신고당한 사람의 메시지와 신고자 본인의 메시지가 함께** 들어 있고, 둘 중 누가 탈퇴해도 남는다. 그래서 목적, 기간, 파기 시점을 정하고 처리방침에 적어야 한다.

| 항목 | 제안 |
|---|---|
| 목적 | 신고 사실 확인, 제재 판단, 이의 제기 검토, 반복 위반 확인, 수사기관의 적법한 요청 대응 |
| 열람 | 신고 운영 담당 2명만(대시보드). 앱 안에서 신고자는 자기 신고(스냅샷 포함)를 볼 수 있는데, 스냅샷은 이미 그 방에서 본 메시지라 추가 노출은 없다 |
| 미처리 신고 | 처리될 때까지 지우지 않는다 |
| 제재 없이 종결 | 종결(`resolved_at`) 후 **6개월**이 지나면 `messages_snapshot`을 비우고 `details`를 지운다. 사유·날짜·당사자 id는 통계와 반복 신고 확인을 위해 1년 보관 후 삭제 |
| 제재하고 종결 | 종결 후 **1년**이 지나면 `messages_snapshot`·`details` 삭제. 제재 기록(대상, 사유 분류, 제재 내용, 날짜)은 **3년** 보관(재가입 확인용) |
| 분쟁·수사 중 | 끝날 때까지 보존한다(보존 결정을 메모로 남김) |
| 탈퇴 | 탈퇴해도 위 기간 동안 스냅샷을 남긴다. 탈퇴 안내 화면과 처리방침에 이를 알린다 |

- 위 기간은 **제안**이다. 개인정보 보호법상 "목적 달성 후 지체 없이 파기" 원칙에 맞는 기간인지, 영구 정지자의 재가입 방지 목적으로 3년이 적절한지는 **법률 전문가 확인이 필요하다**.
- 재가입 방지(B2)를 하려면 영구 정지자의 로그인 식별자(OAuth provider와 subject id)의 해시를 따로 보관해야 한다(M-6). 이것도 처리방침에 적는다.

**처리방침 반영 문안 (en 초안, 번역 필요)**

> When you report someone, we keep a copy of the last 50 messages in that chat, the reported person's display name at the time, and the details you provide. We use this only to review reports, decide on actions and handle appeals. Only our safety team can see it. We keep it even if either person deletes their account: for 6 months after a report is closed, or for 1 year if we took action. We keep a record of the action itself for 3 years to prevent banned members from rejoining.

## 9. 출시 전 필요한 기능 (개발 요구사항)

| ID | 기능 | 필요 시점 | 메모 |
|---|---|---|---|
| **M-1** | **신고 알림**: 새 신고가 들어오면 운영 담당에게 알림. `safety`·`money`는 즉시 | **여행객 대상 홍보 전 필수** | 예: Supabase Database Webhook → 이메일·메신저. 비용이 없는 수단 확인 필요 |
| **M-2** | **차단**: A가 B를 차단하면 B는 A의 요청을 볼 수 없고 새 방을 만들 수 없다. 기존 방에서 양쪽 모두 메시지를 보낼 수 없다. 연락처 공개도 중단(`contact-visibility.md` R7). 차단 사실은 상대에게 알리지 않는다 | **여행객 대상 홍보 전 필수** | `blocks(blocker_id, blocked_id, created_at)` + RLS |

| **M-4** | 처리 기록 컬럼: `resolution`(no_action/warning/suspended_7d/banned/...), `resolution_note`, `handled_by` | 출시 전 필수(S) | 사용자에게 노출하지 않음 |
