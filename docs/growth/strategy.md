## 1. 결론

1. **순서는 가이드 먼저, 여행객은 안전 게이트 통과 후.** 가이드 1기 모집(상위 1) → 가이드가 출연하는 인스타 릴스·Collab(상위 2) → 호스텔 QR 파일럿(상위 3).
2. **동네 2곳에 집중한다.** 홍대·연남, 종로(익선동·북촌·서촌)를 기본안으로 한다(가설). 가이드가 5명 이상 모인 동네의 숙소에만 QR을 둔다.
3. **여행객을 향한 공개 홍보(인스타 프로필의 여행객 링크, 릴스의 요청 유도 문구, 호스텔 QR)는 게이트 T를 통과해야 시작한다.** 핵심은 연락처·인스타 노출 범위 수정, 안전 수칙, 신고 경로다. 그 전까지 인스타 프로필 링크는 가이드 모집 페이지(`/volunteer`)로 건다.
4. **측정은 이미 된다.** 모든 링크에 `utm_source`를 붙이면 온보딩을 마친 가입자가 `signup_attributions`에 채널별로 쌓인다. 대신 방문·클릭 수와 추천은 잡히지 않으니 [metrics.md](metrics.md)의 보완책을 함께 쓴다.

## 2. 목표

북극성 지표(가설): **주간 완료된 만남 수**(`guide_requests.status = 'completed'`). 이 숫자가 오르려면 양쪽이 모두 필요하기 때문이다. 보조 안전 지표(가드레일): 신고 건수와 처리 시간(`reports`).

| 시점 | 목표(가설) | 확인 지표 |
|---|---|---|
| 2주차 말 (11/1) | 가이드 가입 20명, 그중 프로필 완성 70% 이상 | `signup_attributions` role=guide, 프로필 완성률 |
| | 협조 수락 기관 2곳 이상, 가이드 소개 UGC 동의자 3명 | 수동 기록(발송·답신 표) |
| | 인스타 계정 개설과 프로필 세팅 완료 (게시는 게이트 통과·승인 후) | 수동 |
| 4주차 말 (11/15) | 파일럿 동네 2곳에서 활성 가이드 10명 이상 (동네별 5명 이상) | Q11(활성 가이드), Q12(동네별) |
| | 호스텔 비치 2~3곳 (게이트 T 통과 시) | partnerships.md, 코드표 |
| | 여행객 가입 20명, 첫 요청 10건, 매칭 3건, 완료 1건 이상 | Q15 |
| | 요청의 48시간 내 첫 연락 비율 80% 이상 | Q8 |

표본이 30 미만일 때는 비율을 믿지 않는다. 건수와 개별 사례(어디서 막혔는지)를 본다.

## 3. 퍼널

앱 구조상 가이드가 먼저 채팅방을 연다(`chat_rooms` insert는 가이드만 가능). 그래서 "첫 요청"은 여행객 단계, "첫 연락"은 가이드 단계로 나눈다.

| 단계 | 여행객 | 가이드 | 측정 소스 | 지금 측정 가능? | 이탈 가설과 레버 |
|---|---|---|---|---|---|
| 1. 방문 | 인스타 프로필·QR·검색 | 공고·메일·커뮤니티 링크 | 플랫폼 통계 (Insights 링크 탭 등) | 아니오 (앱에 방문 수 없음) | 미리보기 빈약(OG 없음) → 개발 요청 |
| 2. 가입 | 구글/카카오 로그인 | 카카오/구글 로그인 | `profiles` 행 생성(가입 트리거) | 부분 (채널은 모름) | 인스타 등 인앱 브라우저에서 구글 로그인이 막힐 가능성(dev 회의 가설) → 실기기 확인 필요 |
| 3. 온보딩 | 역할 선택 + 프로필 저장 | 역할 선택 + 언어·소개 입력 | `profiles.role is not null`, `signup_attributions` | 예 (채널별·역할별) | 입력 항목이 많으면 이탈. 가이드는 `/volunteer`로 역할 미리 선택됨 |
| 4. 첫 요청 / 첫 연락 | 요청 등록 (`guide_requests`) | 열린 요청에 첫 채팅방 생성 (`chat_rooms`), 첫 메시지 (`messages`) | 위 테이블 | 예 | 가이드 공급 부족이면 요청이 방치됨 → 런칭 순서의 이유 |
| 5. 매칭 | 가이드 수락 (`status = matched`) | 선택됨 (`matched_guide_id`) | `guide_requests` | 예 | 응답 속도, 프로필 신뢰도(사진·소개) |
| 6. 완료 | `status = completed` | 동일 | `guide_requests` | 예 (여행객이 직접 표시, 실제 만남 여부는 모름) | 완료 처리 습관 |
| 7. 재방문/추천 | 2번째 요청, 지인 소개 | 2회 이상 매칭, 지인 가이드 모집 | 요청·매칭 횟수, 가입 7일 후 활동 | 재방문은 예, 추천은 아니오 | 추천은 "어떻게 알게 됐나요" 문항 제안(개발팀 요청 참고) |

두 그룹 균형 규칙(가설):

- 동네별 활성 가이드(최근 14일 안에 채팅방을 연 가이드)가 5명 미만이면 그 동네에는 QR을 비치하지 않는다.
- 요청의 48시간 내 첫 연락 비율이 2주 연속 70% 미만이면, 해당 동네의 여행객 대상 홍보를 멈추고(릴스 문구를 모집용 CTA로 전환, 신규 QR 비치 중단) 가이드 모집을 늘린다.
- 반대로 가이드가 15명 이상인데 요청이 주 3건 미만이면 가이드 모집 공고를 새로 올리지 않고 여행객 채널에 힘을 싣는다. 가이드를 대기시키면 이탈한다.
- 방치된 요청(48시간 이상, 연락 0건, 여행 날짜 미경과)은 매일 Q8b로 확인하고 팀이 수동으로 대응 방법을 정한다(가이드에게 직접 알림을 보내는 것은 사용자 승인 후).

## 4. 시작 조건 (게이트)

모든 게이트의 전제: 외부 행동(게시·발송·공고 등록·계정 개설·방문 제안)은 **사용자 승인 후**에만 한다.

| 게이트 | 허용되는 행동 | 시작 조건 | 확인 방법 | 현재 상태 (2026-10-17) |
|---|---|---|---|---|
| **게이트 P (준비)** | 문서 작성, 링크 QA, 계정 개설(게시 없이) | 없음 | - | 진행 중 |
| **게이트 G (가이드 모집)** | 대학 국제교류 조직·학과 협조 요청, 대외활동 플랫폼 공고, 지인·동아리 대상 소규모 모집, 인스타 프로필 링크를 `/volunteer`로 | ① 가입 연령 기준 확정 ② trust-safety의 모집 문구 검토 ③ 원격 DB에 `0003`(유입 기록·신고) 적용 ④ 운영 주체·문의 이메일 확정 ⑤ 연락처 안내 문구 처리(아래 주의) | 사용자 결정, [review-free-promotion.md](../policy/review-free-promotion.md), Supabase 대시보드에서 `signup_attributions` 존재 확인 | 미충족 (①②④ 대기, ③ 확인 필요) |
| **게이트 U (UGC)** | 가이드·여행객이 나오는 게시물, Collab | [UGC 동의서](../policy/ugc-consent.md) 확정과 출연자별 동의 확보, 소속 표시 문구 확정 | 동의서 사본 보관 | 미충족 |
| **게이트 T (여행객 공개 홍보)** | 인스타 프로필의 여행객 링크, 릴스·캡션의 요청 유도 문구, 호스텔 QR 카드·포스터 비치, 해외 커뮤니티(규칙 확인 후) | ① **연락처·인스타 노출 범위 수정이 배포되고 원격 DB에 적용됨** (dev 회의 1위 보안 묶음, `dev-security-reviewer` 통과) ② [안전 수칙](../policy/safety-guidelines.md) 확정 및 가입·채팅 화면 또는 카드에 반영 ③ 신고 경로 가동: 앱 내 신고(`0003` 적용) + 문의 이메일 + 처리 담당·기한 ④ 파일럿 동네 활성 가이드 5명 이상 ⑤ 개인정보처리방침 공개(trust-safety 판단) | 개발팀 보고, 정책 문서, Q12 | 미충족 |
| **권장 (차단은 아님)** | - | 인스타 인앱 브라우저 로그인 실기기 확인과 대응, OG 미리보기, 개인정보 고지 | dev 회의 5-1, 3위 | 미확인 |

주의 사항:

- **게이트 G의 연락처 문제.** 지금은 로그인한 누구나 `profiles`의 `contact`·`instagram`을 읽을 수 있다(dev 회의 2.1 High). 가이드 후보는 대부분 대학생이므로 대규모 공개 모집(링커리어, 에브리타임)은 이 수정 뒤를 권한다. 그 전에는 (a) 지인·동아리 소규모 모집만 하거나, (b) 공고에 "연락처·인스타는 비워 두고 가입해도 됩니다"를 명시한다. 어느 쪽으로 갈지는 사용자 결정이다. 문안에는 "채팅 상대에게만 보인다"는 표현을 수정 배포 전에 쓰지 않는다.
- **게이트 T의 인스타 링크 전환.** 게이트 T 전에는 프로필 링크를 `/volunteer?lang=ko&utm_source=instagram&utm_medium=bio&utm_campaign=profile_guide`로 둔다. 통과 후 여행객 링크를 첫 번째, 가이드 링크를 두 번째로 둔다(인스타 프로필은 링크를 최대 5개까지 넣을 수 있고 첫 번째만 프로필에 바로 보인다, [Search Engine Land 2023-04](https://searchengineland.com/instagram-now-allows-up-to-5-links-in-bio-395742), 조사일 2026-10-17).
- 게이트 통과 여부는 매주 금요일 10분 점검으로 확인하고, 결과를 이 표의 "현재 상태"에 날짜와 함께 갱신한다.

## 5. 런칭 순서와 동네 집중

### 5.1 단계

| 단계 | 기간(목표) | 내용 | 시작 게이트 | 종료 신호 |
|---|---|---|---|---|
| 0. 준비 | 10/17~10/25 | 문안, 코드표, 링크 QA, 인스타 계정 개설(게시 없음), 결정 사항 확정 | P | 게이트 G 충족 |
| 1. 가이드 1기 모집 | 10/26~11/8 | 협조 요청, 공고, 소규모 모집. 가입 현황 주 2회 점검 | G | 가이드 가입 20명 또는 4주 경과 |
| 2. 가이드 소개 콘텐츠 | 11/2~ | 동의한 가이드 3명과 EP4~6 촬영, 계정에 게시. 요청 유도 문구는 게이트 T 전까지 CTA-A(모집형) | G + U | 릴스 3편 게시 |
| 3. 호스텔 QR 파일럿 | 게이트 T 충족 직후 (목표 11/9~) | 파일럿 동네 숙소 2~3곳에 카드·포스터 비치, 스태프 추천 요청 | T | 4주간 비치 숙소별 가입·요청 확인 |
| 4. 여행객 인스타 확대 | 단계 3과 병행 | 동네 릴스 EP1~3, 프로필 여행객 링크 전환, 가이드 Collab 확대 | T + U | 주간 가입·요청 증가 확인 |
| 5. 차기 후보 | 단계 3 결과 후 | Reddit 질문 답변 참여(규칙 확인 후), 크리에이터 동행 제안, 일본어 X·note, 언어교환 모임 | 아래 6장 조건 | - |

날짜는 목표일 뿐이다. 게이트가 안 열리면 뒤로 밀고, 억지로 당기지 않는다. 2학기 중간고사 기간(대략 10월 셋째~넷째 주, 가설)이라 학교 측 응답이 늦을 수 있고, 방학(12월 중순부터, 가설)에는 가이드 가용 시간이 늘 수 있다. 가을 성수기 여행객을 놓치더라도 첫인상을 지키는 쪽을 택한다.

### 5.2 동네 집중

- **기본안: 홍대·연남, 종로(익선동·북촌·서촌).** 선정 이유(전부 가설): 호스텔·게스트하우스가 많고, 도보로 코스가 짜지고, 대학생 가이드의 거주·생활권과 겹친다. 성수는 콘텐츠 소재(릴스 EP3)로만 쓰고, 가이드가 모이면 3번째 동네로 올린다.
- **가이드 모집 때 동네를 묻는다.** 앱에는 가이드의 활동 동네 필드가 없다. 공고에서 "프로필 소개에 활동 가능한 동네를 적어 주세요"라고 안내한다(문안에 반영됨). 개발 요청은 11장.
- **요청의 `area`는 자유 텍스트다**("e.g. Jongno, Hongdae"). 동네별 집계는 키워드 매칭으로 한다([metrics.md](metrics.md) Q12). 호스텔 QR이 있는 동네의 요청이 그 동네 `area`로 들어오는지는 샘플로 확인한다.
- **한 번에 동네를 늘리지 않는다.** 파일럿 2곳에서 48시간 내 첫 연락 80% 이상을 2주 유지하면 다음 동네를 연다.
- 동네를 정했다면 인스타 콘텐츠, 호스텔 후보, 가이드 모집 메시지가 모두 같은 동네를 말해야 한다.
